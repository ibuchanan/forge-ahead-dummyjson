# DummyJSON contract generation

The pinned source is `vendor/DummyJSON` at the repository gitlink. `reviewed-routes.json` records the source commit against which its route families were independently reviewed: 40 GET declarations mounted under singular and plural prefixes (80 templates); the two optional random `length` routes expand to 84 concrete paths. It also records endpoint-specific query groups and response shapes, reviewed against `clean-request.js`, the route handlers, `paginateResource` and the controllers. Authentication-protected `/user/me` and `/users/me`, mutations and utility routers are excluded.

The checked-in [OpenAPI contract](dummyjson.openapi.json) is the reviewed source of truth for endpoint types. To refresh it deliberately after reviewing a pinned-source change:

1. Run `bun run generate:contract`. The TypeScript AST extractor first requires the checked-out submodule commit to match `reviewed-routes.json`, then compares mounted GET paths with the reviewed inventory and fails on missing/extra routes or unsupported path/mount syntax. After reviewing a submodule update, update the inventory's `sourceCommit` with its reviewed route semantics. The script invokes the locally installed, pinned `quicktype` on the eight local dataset files to draft record schemas; it does not call the live API. Review the resulting contract diff, including new field names and applicable query parameters. Never add record examples from the users dataset.
2. Run `bun run generate:types` to regenerate `src/generated.ts` from the committed contract using `openapi-typescript`.
3. Run `bun run contract:check` to compare source routes with the reviewed inventory, compare reviewed route semantics with the committed contract, and compare regenerated types byte-for-byte. The command is read-only, does not run `quicktype`, and is intentionally excluded from routine checks; run it after updating the submodule, reviewed route semantics, inferred schemas, or generated types.

The controller returns `{ products|users|carts|posts|comments|todos|recipes|quotes, total, skip, limit }` for paginated routes; `limit` is the effective returned count. Detail routes return records, tag/category lists return arrays, and `/random` returns one record while `/random/{length}` returns an array (invalid lengths return `[]`). Cross-resource routes use the *response* resource's page envelope. Product date filters apply to product list, search and category routes, not detail/category discovery. `q` applies only to searches; `key`/`value` only to user filter. `select` changes item and page projection where forwarded by a handler; user-cart pages forward only `limit`/`skip`.

Dataset-inferred fields, nested objects and formats are drafts, **not a guarantee that fields always appear**. Record properties are optional in the contract because `select` and dataset revisions change the shape; quicktype's closed enums, all-required lists, and `additionalProperties: false` are discarded. User `password` and `ssn` are sensitive *field names* present in source records: no values or examples are included. Middleware's `delay` is not a resource-controller parameter and is intentionally omitted. The initial scaffold does not enumerate HTTP error response bodies; the client layer will handle status/error outcomes separately.
